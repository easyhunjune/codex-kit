# 검증과 기록

1. 바꾼 부분의 테스트를 쓰거나 고친 뒤 실행하고, 출력 요약을 사용자에게 보여 준다.
2. 웹 화면이 있으면 서버를 0.0.0.0으로 띄우고 포트와 경로를 알려 사용자가 Browser에서 직접 확인하게 한다.
3. 테스트가 실패하면 테스트를 고쳐서 통과시키지 않는다. 원인부터 설명한다.
4. 커밋한다. 메시지 첫 줄에 무엇을 바꿨는지, 둘째 줄에 왜 바꿨는지 쓴다.
5. 작업 기록(기본 `docs/LOG.md`)에 아래 형식으로 덧붙인다.

```
## [경과 분] 마일스톤 이름
- 작동 방식: 입력이 어떤 단계를 거쳐 출력이 되는지 2줄
- 실패할 수 있는 경우: 어떤 입력이나 상황에서 깨지는지
- 검증: 실행한 명령과 결과
- 확인과 수정: 사용자가 제안을 확인하거나 고친 내용과 이유, 검증에서 드러난 AI 출력의 오류 (없으면 생략)
- 위임: 맡긴 일과 채택 여부 (없으면 생략)
```

6. 실제로 있었던 일만 작업 기록에 적는다. 확인과 수정 칸을 채우려고 일을 지어내지 않는다.
