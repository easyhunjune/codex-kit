# 위임

## 역할
| 역할 | 맡기는 일 | 모델 | effort | 파일 쓰기 |
|---|---|---|---|---|
| 메인 | 판단, 설계, 통합, 사용자와의 대화 | Sol 6.1 | 기본값 | 가능 |
| reader | PDF와 긴 문서에서 필요한 부분만 발췌 | Luna 6.0 | low | 불가 |
| searcher | 공개 문서와 라이브러리 사용법 검색 | Luna 6.0 | low | 불가 |
| worker | 인터페이스가 정해진 독립 모듈, 테스트 작성 | Luna 6.0 | high | 지정 파일만 |
| reviewer | 마일스톤 diff 검수 | Luna 6.0 | high | 불가 |

표의 모델 이름은 표시명이다. 실행할 때는 `/model` 목록에 나온 정확한 이름을 쓴다.

## 맡기지 않는 것
- 핵심 로직 설계와 여러 파일에 걸친 통합
- 사용자에게 할 질문과 사용자 결정이 필요한 판단
- 같은 파일을 고치는 두 작업의 동시 실행

## 지시문 형식
하위 에이전트는 이 대화를 보지 못한다. 필요한 것을 지시문에 모두 넣는다.
- 목표 한 줄
- 읽을 파일 경로. worker에게 쓸 파일 경로도 정해 주고 그 밖의 파일을 건드리지 않게 한다
- 산출 형식과 길이 상한. reader는 쪽 번호를 붙인 발췌, searcher는 출처 URL을 붙인 요점, reviewer는 심각도 순 문제 목록
- 하지 말 것. searcher의 검색 질의에 과제 자료와 데이터를 넣지 않는다

## 실행
위에서부터 되는 방법을 쓴다.
1. 하위 에이전트 생성 도구(spawn_agent)가 있으면 그 도구로 띄우고, 역할 표의 모델과 effort를 호출 인자로 지정한다.
2. 없으면 셸에서 비대화 실행으로 띄운다.
   - reader, searcher, reviewer: `codex exec -m <모델> -c 'model_reasoning_effort="<effort>"' "<지시문>"` (기본이 읽기 전용이다)
   - worker: 위 명령에 `--sandbox workspace-write`를 붙인다
3. 둘 다 안 되면 새 터미널 탭에서 codex를 하나 더 띄워 달라고 사용자에게 요청하고, 지시문을 그대로 넘긴다.

## 결과를 받으면
- 메인이 직접 확인한다. reader 발췌를 원문 한두 곳과 대조하고, worker 코드를 테스트한 뒤 통합한다.
- 메인이 reviewer 지적마다 채택 여부를 판단하고 이유를 남긴다.
- 작업 기록의 위임 칸에 무엇을 맡겼고 무엇을 채택했는지 적는다.
