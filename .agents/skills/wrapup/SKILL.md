# 마감

1. 사용자가 따로 지시하지 않으면 새 기능을 추가하지 않고, 깨진 것만 고친다.
2. 전체 테스트를 실행하고 결과를 작업 기록에 적는다.
3. 계획 문서의 완료 기준을 하나씩 대조해 충족 여부를 표로 적는다.
4. 요약 문서(기본 `docs/SUMMARY.md`)를 아래 칸으로 쓴다. 칸마다 5줄 이내로 쓴다.
   - 구조: 주요 파일과 역할, 데이터 흐름
   - 핵심 판단: 고른 방식, 근거, 버린 대안
   - 검증: 실행한 테스트와 결과, 확인하지 못한 것
   - 한계와 실패 가능성: 어떤 입력이나 상황에서 깨질 수 있는지
   - 과제 요구와 다른 점: 구현이 요구와 다르면 그 차이와 이유
5. 과제 안내의 필수 파일이 모두 제 경로에 있는지 확인하고, 실행 방법을 README에 적는다.
6. 마지막으로 커밋하고, 제출 전에 요약 문서를 읽으라고 사용자에게 알린다.
